#### 1) Определение адреса сети.

- Для определения адреса сети необходимо выполнить следующую команду:
  ```bash
  ipcalc 192.167.38.54/13
  ```

- Результат выполнения команды отражен на скриншоте ниже.

  ```
  Network:   192.160.0.0/13       11000000.10100 000.00000000.00000000
  ```

#### 2) Перевод масок.

**a.** Для перевода маски `255.255.255.0` в префиксную и двоичную запись необходимо:
- Выполнить следующую команду:
  ```bash
  ipcalc 255.255.255.0
  ```

- Результат выполнения команды отражен на скриншоте ниже.
  ![1.1.2a](images/Screenshot%202025-01-22%20at%201.46.20%20AM.png)

- Искомое значение отражено в следующей строке:
  ```
  Netmask:   255.255.255.0 = 24   11111111.11111111.11111111. 00000000
  ```
  
- Отсюда следует, что:
  - Префиксной записью маски является значение: `/24`.
  - Двоичной записью маски является значение: `11111111.11111111.11111111.00000000`.

**b.** Для перевода маски `/15` в обычную и двоичную запись необходимо:
- Выполнить следующую команду:
  ```bash
  ipcalc 0.0.0.0/15
  ```

- Результат выполнения команды отражен на скриншоте ниже.
  ![1.1.2b](images/Screenshot%202025-01-22%20at%202.06.00%20AM.png)

- Искомое значение отражено в следующей строке:
  ```
  Netmask:   255.254.0.0 = 15     11111111.1111111 0.00000000.00000000
  ```

- Отсюда следует, что:
  - Обычная запись: `255.254.0.0`
  - Двоичная запись: `11111111.11111110.00000000.00000000`

**c.** Для перевода двоичной формы маски `11111111.11111111.11111111.11110000` в обычную и префиксную необходимо:
- Посчитать каждый октет (набор из 8 битов). Тогда получается следующая запись:
  - `11111111 = 255`
  - `11111111 = 255`
  - `11111111 = 255`
  - `11110000 = 240`

- В результате расчетов получается обычная запись: `255.255.255.240`.
- Теперь можно проверить данные расчеты, используя следующую команду (необходимо полученный в расчетах адрес записать как маску):
  ```bash
  ipcalc 0.0.0.0/255.255.255.240
  ```

- Результат выполнения команды отражен на скриншоте ниже.
  ![1.1.2c](images/Screenshot%202025-01-22%20at%202.28.25%20AM.png)

- Искомое значение отражено в следующей строке:
  ```

  ```

- Отсюда следует, что префиксная запись: `/28`.

### 1.2. localhost

> IP-адреса, начинающиеся с `127.`, относятся к localhost. Например, `127.0.0.1` — это localhost. Подобные IP-адреса считаются локальными и могут использоваться для обращения к приложениям на текущем компьютере.

**a.** Для проверки можно воспользоваться командой: `ipcalc 194.34.23.100`.

- Результат её вызова отражен на рисунке ниже.
  ![1.2a](images/Screenshot%202025-01-22%20at%203.30.55%20AM.png)

- `194.34.23.100` относится к внешнему IP, так как принадлежит классу C.
  > Class C: 192.0.0.0 – 223.255.255.255 (первый октет от 192 до 223).

**b.** Для проверки можно воспользоваться командой: `ipcalc 127.0.0.2`.

- Результат её вызова отражен на рисунке ниже.
  ![1.2b](images/Screenshot%202025-01-22%20at%203.31.24%20AM.png)

- `127.0.0.2` относится к локальному адресу, так как имеет специальную пометку `Loopback`.

**c.** Для проверки можно воспользоваться командой: `ipcalc 127.1.0.1`.

- Результат её вызова отражен на рисунке ниже.
  ![1.2c](images/Screenshot%202025-01-22%20at%203.31.44%20AM.png)

- `127.1.0.1` относится к локальному адресу, так как имеет специальную пометку `Loopback`.

**d.** Для проверки можно воспользоваться командой: `ipcalc 128.0.0.1`.

- Результат её вызова отражен на рисунке ниже.
  ![1.2d](images/Screenshot%202025-01-22%20at%203.32.03%20AM.png)

- `128.0.0.1` относится к внешнему IP, так как принадлежит классу B.
  > Class B: 128.0.0.0 – 191.255.255.255 (первый октет от 128 до 191).

## Part 3. Утилита **iperf3**

*В данном задании используются виртуальные машины ws1 и ws2 из Части 2*

*Для установки утилиты iperf3 (утилита для измерения производительности сети) необходимо воспользоваться следующей командой:*
```bash
sudo apt install iperf3
```

### 3.1. Скорость соединения

*Перевод осуществляется вручную, по правилам 1 Байт = 8 бит.*
- 8 Mbps = 1 MB/s
- 100 MB/s = 819200 Kbps
- 1 Gbps = 1000 Mbps

### 3.2. Утилита iperf3
- Для тестирования производительности сети необходимо на одной машине запустить утилиту в режиме сервера, а на другой - клиента.
- Пусть машина `ws1` будет в роли сервера. Тогда для запуска необходимо воспользоваться командой `iperf3 -s`.
  В результате будет открыт порт для прослушивания как показано на рисунке ниже.
  ![3.2.1_ws1](images/Screenshot%202025-01-22%20at%2010.01.22%20PM.png)
- Пусть машина `ws2` будет в роли клиента. Тогда для запуска необходимо воспользоваться командой `iperf3 -c 192.168.100.10`.
  В результате будет запущен тест сети и результаты будут отображены как на рисунке ниже.
  ![3.2.1_ws2](images/Screenshot%202025-01-22%20at%2010.04.01%20PM.png)
- По скриншоту выше можно выделить ключевые показатели для `Sender` (отправителя) и `Receiver` (получателя), которые будет примерно равны:
  - объем переданных данных: `2.24 GBytes`
  - скорость передачи данных: `1.92 Gbits/sec`

#### 4.1. Утилита **iptables**

> `iptables` — это утилита в Linux, которая позволяет настраивать правила фильтрации сетевого трафика (сетевой экран или файрвол). 

- Первоначальным шагом будет создание файла `/etc/firewall.sh`, имитирующего файрвол, на `ws1` и `ws2` со следующим содержимым:
  ```bash
  #!/bin/sh

  iptables -F
  iptables -X
  ```
  Используемые флаги выполняют следующие действия:
  - `-F`: Очищает все правила в таблице filter (таблица по умолчанию для iptables).
  - `-X`: Удаляет все пользовательские цепочки (chains), которые были созданы ранее.
- Для каждой из машин необходимо разрешить входящие соединения на порт 22 (SSH), а также на порт 80 (HTTP). Для этого следует воспользоваться следующими схожими командами:
  ```bash
  iptables -A INPUT -p tcp --dport 22 -j ACCEPT
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT
  ```
  Если подробнее рассмотреть команду, то получается:
  - `-A INPUT`: Добавляет правило в цепочку INPUT (для входящего трафика).
  - `-p tcp`: Указывает, что правило применяется только к TCP-трафику.
  - `--dport 22`: Указывает порт назначения (22 - SSH или 80 - HTTP).
  - `-j ACCEPT`: Принимает пакет, если он соответствует правилу.
- Для каждой из машин необходимо применить разрешаюшие и запрещающие правила. Эти правила будут выглядеть следующим образом:
  ```bash
  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j DROP
  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j ACCEPT
  ```
  Если подробнее рассмотреть команды, то получается:
  - `-A OUTPUT`: Добавляет правило в цепочку OUTPUT (для исходящего трафика).
  - `-p icmp`: Указывает, что правило применяется к ICMP-трафику (используется для ping).
  - `--icmp-type echo-reply`: Указывает тип ICMP-пакета (ответ на ping).
  - `-j DROP`: Блокирует пакет, если он соответствует правилу (будет работать только, если идёт раньше, чем правило ACCEPT).
  - `-j ACCEPT`: Разрешает отправку пакетов, если он соответствует правилу (будет работать только, если идёт раньше, чем правило DROP).
- Для `ws1` необходимо сделать так, чтобы она не могла пинговаться. Для этого будет применено запрещающее правило `echo-reply`, а в конце разрешающее. В результате получится следующий код скрипта:
  ```bash
  #!/bin/sh

  iptables -F
  iptables -X

  iptables -A INPUT -p tcp --dport 22 -j ACCEPT
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT

  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j DROP
  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j ACCEPT
  ```

  ![4.1.1_ws1](images/Screenshot%202025-01-23%20at%2010.54.24%20PM.png)

  ```bash
  iptables -A INPUT -p tcp --dport 80 -j ACCEPT

  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j ACCEPT
  iptables -A OUTPUT -p icmp --icmp-type echo-reply -j DROP
  ```

### 5.2. Включение переадресации IP-адресов

## Part 6. Динамическая настройка IP с помощью **DHCP**

  ```
  subnet 10.100.0.0 netmask 255.255.0.0 {}

  subnet 10.20.0.0 netmask 255.255.255.192

      range 10.20.0.2 10.20.0.50;
      option routers 10.20.0.1;
  ```

  - `option routers`: Указывает IP-адрес маршрутизатора по умолчанию.
  - `option domain-name-servers`: Указывает IP-адрес DNS-сервера.

- Включение SNAT, а именно маскирование всех локальных IP из локальной сети, находящейся за r2 (по обозначениям из Части 5 — сеть 10.20.0.0).

  - `iptables -t nat -A POSTROUTING -o enp0s3 -s 10.20.0.0/26 -j SNAT --to-source 10.100.0.12` - эта команда добавляет правило в цепочку POSTROUTING таблицы nat, которое выполняет маскирование источника (SNAT) для всех пакетов, исходящих с интерфейса enp0s3 и имеющих источник в подсети 10.20.0.0/26. Источник этих пакетов будет заменен на 10.100.0.12.
  - `iptables -t nat -A PREROUTING -i enp0s3 -p tcp --dport 8080 -j DNAT --to-destination 10.20.0.20:80` - эта команда добавляет правило в цепочку PREROUTING таблицы nat, которое выполняет перенаправление портов (DNAT) для всех TCP-пакетов, входящих на интерфейс enp0s3 и направляющихся на порт 8080. Эти пакеты будут перенаправлены на IP-адрес 10.20.0.20 и порт 80.
